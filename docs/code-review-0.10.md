# Separate audio and integration review — Flux 0.10

Date: 2026-10-21. This source review covers the new composition path and the final shared-workspace UI, session and generated-file changes. It supplements the previous engine/storage/lifecycle reviews; it is not an independent penetration test or a claim of complete IDM parity.

| Finding                                                                                                                                                             | Resolution / evidence                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Separate MP4 sources can reuse track IDs and have different timescales, fragment boundaries and initial timestamps.                                                 | Combine validated video-only/audio-only initialization metadata, assign track IDs 1/2, remap fixed-width fragment fields and retain relative sample addresses. One shared origin preserves the relationship between tracks. Conservative start, cumulative-duration and end alignment checks refuse incompatible sources. Fixture source IDs deliberately collide. Encoded sample identity and actual Chrome decoding/seek/audio markers verify the exported output.                                                                                                                                                                        |
| An independent audio source must participate in recovery, rather than appearing only in the UI.                                                                     | Selected audio URL/label persist in jobs, cancel/redownload, periodic templates and version-3 URL lists. Paired initialization/first-media output commits both source identities together. Reopening revalidates both sources, including weak-validator byte comparisons and AES key fingerprints. Clear/encrypted jobs survive full browser restart without replaying strongly validated retained media. Missing audio-origin access stops before video initialization.                                                                                                                                                                    |
| Two-source key/probe traffic can exhaust each allowance without ever completing a pair.                                                                             | Require the complete compound part and retained-key verification cost to fit one window. Both sources share existing throttle, allowance and host admission. Unit/HTTP regressions cover this boundary and checkpoint rollback.                                                                                                                                                                                                                                                                                                                                                                                                             |
| Review cache could add two aliases per result while pruning only one entry.                                                                                         | Bound each insertion independently to 16 entries. The cache stores reviewed origins, not authorization to bypass later host checks.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Final concurrent changes used `credentials: include` on every request, including unrelated redirect and manifest/key origins. Documentation still claimed omission. | Default network policy now omits credentials. A real per-download cookie choice authorizes only the original source origin; every other origin omits credentials even with host access. Add Download initially enables this visible choice; capture enables it under explicit capture consent. Imports and legacy jobs remain omitted. No cookie API/value scraping or page-header copying. Unit tests and an actual Chrome cookie-protected endpoint verify omission; a cookie-bearing CDN fixture receives no cookie through a redirect. Browser authentication policies still apply.                                                     |
| Cookie UI was read-only, and its CSS also disabled pointer events.                                                                                                  | The control now changes persisted job behavior and HLS inspection. Unchecked state is visible and interactive. A real browser test caught the CSS issue, which was fixed before final verification. Referrer/user-agent rows report actual fixed behavior instead of disabled pretend controls.                                                                                                                                                                                                                                                                                                                                             |
| Generated-file messages lacked sender-bound grants, chunk/total limits, single-use consumption, synchronization and idle cleanup.                                   | Session grants bind exact tab/frame/document/source URL and total size. Authorization precedes abort as well as payload handling; current capture/exclusions/host access are rechecked. Grants have eight slots and one-hour expiry. A receiver accepts at most 256 KiB decoded chunks, acknowledges writes, rejects overlap/order/size/base64 errors, consumes tokens before publication and removes incomplete files after two minutes idle. A cleanup barrier prevents orphan removal from racing reception. Regression cases cover forged aborts, malformed/oversized input, replay, overlap, storage failure, cleanup and empty files. |
| Generated files stored their source page as an ordinary URL, so retry/export/repeat could download the page HTML.                                                   | A durable non-replayable `pageFile` flag blocks source refresh, network restart/redownload/browser fallback, periodic templates and URL-list export. Already generated legacy records with the exact old creation note are migrated. The verified local copy remains exportable; a fresh copy must be created on the website.                                                                                                                                                                                                                                                                                                               |
| New generated-file handoff has different lifetime and memory properties from HTTP streaming.                                                                        | A conservative 1 GiB page-file admission cap falls back to Chrome; actual acceptance covers smaller multi-chunk files. Content scripts materialize a browser Blob before slicing; the message chunk bound does not prove total native/browser memory. Interrupted ingestion must be recreated. Script-triggered takeover retains Chrome's original until a verified staged replacement exists. No 1 GiB ingestion capacity claim is made.                                                                                                                                                                                                   |
| Broad scheduling acceptance sometimes read the job before asynchronous addition completed.                                                                          | The test helper now waits for Add Download to close after durable admission. The observed failure was an undefined job, not a wrong queue state. Final evidence records the failed attempt separately from corrected verification.                                                                                                                                                                                                                                                                                                                                                                                                          |

The final package retains the previous MV3 permissions, optional website grants and local CSP. Runtime processing stays in Chrome; no account, native helper, remote conversion service or new dependency was added. Existing HTTP range, corruption, cancellation, export, original-browser-transfer and service-worker termination regressions remain part of the broad suite.

Design references: [RFC 8216 alternate renditions](https://datatracker.ietf.org/doc/html/rfc8216), [ISO BMFF media byte-stream requirements](https://www.w3.org/TR/mse-byte-stream-format-isobmff/), [Fetch credential modes](https://fetch.spec.whatwg.org/#concept-request-credentials-mode), [Chrome network security](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests#security-considerations), [Chrome message serialization and sender validation](https://developer.chrome.com/docs/extensions/develop/concepts/messaging).

Long-media memory, arbitrary media layouts, continuous TS between keyframes, separate TS audio, split program sections, live/discontinuities, other encryption, DASH, crawling and localization remain open. Native destination consent, macOS, crash/power-loss durability and 5/10 GiB are unproven. See [verification](verification-0.10.md) and the [complete capability audit](feature-parity.md).
