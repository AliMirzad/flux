# Implementation review - 0.7 work

Date: 2026-10-21. This is a source review with regression evidence, not an independent security certification or a claim of full IDM parity.

## Findings addressed

An additional real-Chrome regression reproduced lost clicks after extension-context invalidation: the old content script prevented the click before a synchronous messaging exception, and neither downloader started within ten seconds. The fix checks runtime availability before intercepting, routes synchronous messaging exceptions through the browser fallback, and disposes old listeners on reinjection. The same test now produces Chrome's original download, while normal/reconnected Flux capture remains duplicate-free. Manual extension-card Reload/re-enable behavior remains a separate UI gate; the CDP-loaded fixture's runtime reload invalidates it without automatically re-enabling its entry.

## Review scope

- Engine: range status/bounds/validators, single-stream fallback, body length, retry classification, abort/flush/close ordering, final coverage and hash verification.
- Integration: trusted message senders, capture eligibility, excluded parent/target hosts, bounded request/redirect metadata, native GET handoff, original POST/session/blob/data preservation, host consent and service-worker startup handshake.
- Orchestration: single-owner lock, queue/window/allowance dispatch, persistence before retries, manual stop, repeat-run transactions, worker failure, staged-versus-exported state and destination errors.
- Media: manifest/child URL validation, worker-only ordered staging, bounded metadata, sample payload addresses and timelines, per-part checkpoints, source revalidation, destination verification and page-discovery review flow.
- Interface/package: real job actions, optional permissions, local executable assets/CSP, versioned lists, diagnostics and privacy disclosures. No new runtime dependency or manifest permission was added.

## Work still required

HLS support currently covers completed, unencrypted fragmented-MP4 H.264/AAC renditions with their selected tracks already together. MPEG-TS transmuxing, separate audio/language composition, ordinary non-DRM encryption, live recording, discontinuity remuxing and DASH are not complete. The [capability audit](feature-parity.md) retains these requirements, the crawler and localization work.

Tests run in isolated Chrome profiles. The verified files were copied into the existing installed path with a backup and unchanged permissions. After Reload and website refresh, the user confirmed version 0.7.0 is active and the download starts. Its broad HTTP/HTTPS grant was present during read-only inspection; the IndexedDB capture switch and live errors were not inferred from that grant. Native consent UI, macOS, 5/10 GiB capacity, power-loss and process-memory acceptance remain unproven. No production-ready or complete-parity claim follows from the test suite.
