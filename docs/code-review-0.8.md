# Media implementation review — 0.8

Date: 2026-10-21. Review of the TS conversion addition and its integration with the previously reviewed download, storage and export paths. This is a source review with regression evidence, not an independent security certification or full IDM parity.

| Finding                                                                                                 | Resolution and evidence                                                                                                                                                                                                                                                                                                                                               |
| ------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The candidate AAC parser could loop forever on zero/undersized frame lengths.                           | Pin mux.js 6.3.0; reject undersized frames, invalid rates and more than 32,768 frames per logical part. A Node child test has its own termination deadline, and actual Chrome rejects a malformed ADTS source without a checkpoint before completing another TS download.                                                                                             |
| A fresh video converter could silently discard frames before a later keyframe.                          | Refuse parts that start between keyframes or lack the required access-unit delimiter. Bound NAL count and size. Compare every encoded video frame and AAC sample in actual exported output with the independently generated source. Continuous remuxing remains open.                                                                                                 |
| A parser running in the main download worker could prevent cancellation or further transfers.           | Use a dedicated, packaged child worker with one outstanding acknowledged request, transferred owned buffers and a ten-second operation deadline. Abort/error/timeout terminate the child and reject the pending operation. Unit tests verify cancellation and deadline cleanup.                                                                                       |
| Fetch chunk bounds alone did not bound retained converter state.                                        | Cap a complete logical TS source at 16 MiB, metadata at 1 MiB, output at 17 MiB, video at 65,536 NALs and audio at 32,768 frames. Validate packet framing, continuity, adaptation, current single-section PAT/PMT and CRC before conversion. Reject unsupported programs/codecs/discontinuities. These are allocation/input limits, not measured peak process memory. |
| Generated fragments were suited to MSE append, with unknown initialization duration and implicit bases. | Reset unknown fragmented initialization durations; mark the equivalent relative moof base, preserve sample addresses, normalize the common track origin and inspect all first-track occurrences across moofs. Ordinary Chrome decodes and seeks the actual saved MP4.                                                                                                 |
| TS does not directly carry the last video frame duration.                                               | Use the bounded EXTINF interval to correct only the last sample duration; preserve encoded payload. Unreasonable corrections are refused. Adjacent AAC clock quantization is clamped within two samples. Tests cover the 33-bit clock rollover.                                                                                                                       |
| Converted output length differs from the fetched source length.                                         | Persist distinct source hash/size/validator and output extent/hash. Commit source identity with output progress only after flush. Full Chrome restart revalidates the old source with HEAD without replaying its payload; resumed output is byte-identical to uninterrupted output.                                                                                   |
| First-part checkpoint failure could leave initialization/timeline fields from uncommitted output.       | Restore initialization fingerprint/boundary, origin, track ends and segments on failure. Quota failure followed by retry verifies the rollback.                                                                                                                                                                                                                       |

The converter is a locally bundled Apache-2.0 module. `scripts/vendor-media.mjs` verifies exact upstream source hashes before applying the reviewed patches. Regeneration reproduced SHA-256 `c6708d072571ae8927589fc33b2fb1ba5d91bc48dc17c6d7496dfd3053dc7047`; licensing and changes are included in the package notices. There is no remote executable import, native media tool, processing backend, new permission or idle keepalive.

Other download/capture/storage/export review coverage is retained in [0.7 review](code-review-0.7.md). Remaining media work includes continuous non-keyframe TS parts, split program sections, separate audio/languages, ordinary non-DRM encryption, live/discontinuities and DASH. Site crawling and localization also remain in the [capability audit](feature-parity.md). Long media, sustained total memory, native consent UI, macOS and 5/10 GiB acceptance remain unproven.
