# Flux privacy policy

Applies to Flux 0.10.0.

Flux processes downloads locally in your Chrome profile. It has no account system, analytics SDK, telemetry endpoint, advertising tracker, or download-processing backend. It makes HTTP requests to the download addresses you approve. Those servers receive your IP address and ordinary request information. The Add Download cookie option and explicit automatic-capture opt-in can authorize Chrome-managed session credentials for the original download origin. Other origins, including redirect destinations and media/key CDNs, receive no credentials. Imports and programmatic additions default to omission. Referrers are always omitted. Flux never reads cookie values or copies page authorization headers. Browser cookie policy can still deny a session. Original browser transfers retain Chrome's own session and request behavior; Flux does not read those credentials or request bodies. Chrome and the operating system can make their own connections independently of Flux.

Optional download-allowance counters and their reset windows are stored locally to preserve limits after a restart. Optional completion tones are synthesized locally after user activation and do not contact a sound service. Queue schedules and repeated-run metadata also remain local.

Optional automatic retries store a transient-failure classification, timestamps, attempt count and next retry time locally. Retries contact the original approved public file address again after bounded delays and reuse only verified local checkpoints. They respect queue windows and host permissions. Manual pause clears the pending automatic retry. This policy is off by default and does not replay original Chrome/POST transfers.

Flux stores source URLs (including signed query parameters), filenames, sizes, progress, checksums, diagnostic events, settings, and partial file content locally. Signed URLs can contain secrets; people with access to your device or Chrome profile may be able to read this data. Flux does not add encryption to Chrome's profile storage.

HLS review fetches the playlist you choose and can request access to its child resource origins before downloading. Approved media downloads contact initialization/segment servers and persist their source URLs, validators, source hashes, output hashes and timeline checkpoints locally for recovery. User-invoked media discovery can also inspect the last 2,000 resource URL entries in the selected accessible page for playlist addresses. It does not read their bodies, cookies or credentials. Integration inspection reports local version, capture/permission and script-registration status; reconnect reapplies existing capture configuration without broadening access or uploading diagnostics.

Supported MPEG-TS parts are converted to MP4 locally in a packaged child worker. Source bytes and converted output remain in the browser; no media conversion service or native application receives them.

For ordinary identity AES-128 HLS, Flux fetches the public key resources referenced by your approved playlist under the same website permissions. Decryption uses local Web Crypto. Temporary raw keys are not saved in history, checkpoints, URL-list exports or diagnostics. Only a key fingerprint is retained with the ciphertext source checkpoint to detect changed keys on resume. Decrypted staged media remains local and is not encrypted by Flux at rest. DRM license requests and sample-encryption workflows are not supported.

The unlimitedStorage permission exempts local extension storage, including staged file content, from Chrome's normal quota and eviction rules. It does not grant website access or permission to write arbitrary folders. Disk exhaustion and user deletion can still remove or prevent local data. Host access is requested for websites you choose. Enabling automatic capture requests access to HTTP/HTTPS websites so eligible links on existing and future tabs can be handled. Capture is optional and disabled until you enable it. Content scripts inspect clicked links under your configured file and site rules. Read-only webRequest observers keep bounded, in-memory URL/method/initiator/tab metadata for up to 30 seconds to distinguish public GET downloads from POST requests. Redirect destinations for Flux's own requests are held for up to five seconds so each hop can be validated. Cookie values, page authorization headers and POST bodies are not read or forwarded by Flux code; Chrome manages the explicitly selected source session. Temporary browser-fallback decisions expire after one minute. Linked original browser rows retain Chrome's download ID, start time, public source reference, filename, progress and status locally. For trusted blob/data download clicks, up to 64 single-use page attribution hints retain a public source-page URL, parent hostname, kind and random filename prefix in session storage; they expire logically after 15 minutes and are pruned on access. Approved page blob/data files up to 1 GiB can instead pass through acknowledged 256 KiB JSON/base64 messages into OPFS. Up to eight random session grants bind source URL, tab, frame, document, size and issue time; they expire within one hour and are consumed on completion or abort. Incomplete receivers are cleaned after two minutes idle. The manager rechecks capture, exclusions and grants. Generated file content and its checksum are staged locally; history records the public source page, not the blob/data payload URL. Interrupted ingestion must be recreated on the website. Script-generated blob takeover removes Chrome's original file only after a verified staged Flux copy exists; failed handoff leaves Chrome responsible. Legacy review candidates from an earlier version can remain in session storage until dismissed or the session ends. User-invoked link/media discovery reads up to 2,000 link URLs and direct media URLs from an accessible web page for review. Batch imports and exports process the URL lists you choose locally; exported lists can include signed URL queries. Blob/data entries are excluded from exported link lists. These features do not upload observations to Flux servers. Notifications are optional and show a filename when a transfer is ready to save.

OPFS content remains inside Chrome until a verified file is saved to the configured destination. Automatic saving defaults to Chrome's Downloads folder and can create configured category subfolders. You can disable it or explicitly approve another folder; that directory handle is stored locally. Chrome can require renewed folder permission. No folder access is granted silently. Saving creates a second copy. Remove a download to delete its staged content and local record. Clear history removes completed/canceled records and their staged copies. Clean temporary data removes orphaned staging files and exported records older than the configured retention period; unfinished tracked downloads are retained. Retention cleanup is user invoked in this version. Deleting profile storage or uninstalling Flux can remove local records and staged files. Exported destination files are managed by you and are not deleted by Flux's history cleanup.

You can revoke website access and notifications in Chrome or Flux settings, disable automatic capture, exclude websites, and delete local download data. When capture is enabled, eligible clicked file links queue directly in Flux. For other native downloads, Flux can pause a known public GET, probe it under the source-origin session policy, persist the replacement job, and only then cancel Chrome's transfer. Requests that cannot be reproduced safely retain their original Chrome download, which can be controlled through its linked Flux row. Removing an unfinished browser row cancels that request; removing any browser row deletes only Flux's record and leaves Chrome history and saved files intact. Chrome retains its own authentication, destination and security behavior. Original browser transfers are not staged in OPFS or hashed by Flux and may continue while the manager is closed and Chrome remains open.

Before any public store distribution, the distributor must provide publisher identity and contact information alongside this policy and reconcile it with the exact shipped version. This repository does not publish the policy or transmit any information on your behalf.

User-invoked site crawling reads bounded same-origin linked pages and robots rules as inert HTML, applies configured limits, and returns candidates for batch review. It does not execute page scripts or send scan results to a service. Dynamic DASH/HLS recordings keep a bounded local manifest snapshot and selected track identities so retained content can be finished after interruption.
