# Flux privacy policy

Applies to Flux 0.6.0.

Flux processes downloads locally in your Chrome profile. It has no account system, analytics SDK, telemetry endpoint, advertising tracker, or download-processing backend. It makes HTTP requests to the download addresses you approve. Those servers receive your IP address and ordinary request information. Requests from the Flux engine omit cookies, HTTP credentials, and referrers. Original browser transfers retain Chrome's own session and request behavior; Flux does not read those credentials or request bodies. Chrome and the operating system can make their own connections independently of Flux.

Optional download-allowance counters and their reset windows are stored locally to preserve limits after a restart. Optional completion tones are synthesized locally after user activation and do not contact a sound service. Queue schedules and repeated-run metadata also remain local.

Optional automatic retries store a transient-failure classification, timestamps, attempt count and next retry time locally. Retries contact the original approved public file address again after bounded delays and reuse only verified local checkpoints. They respect queue windows and host permissions. Manual pause clears the pending automatic retry. This policy is off by default and does not replay original Chrome/POST transfers.

Flux stores source URLs (including signed query parameters), filenames, sizes, progress, checksums, diagnostic events, settings, and partial file content locally. Signed URLs can contain secrets; people with access to your device or Chrome profile may be able to read this data. Flux does not add encryption to Chrome's profile storage.

Host access is requested for websites you choose. Enabling automatic capture requests access to HTTP/HTTPS websites so eligible links on existing and future tabs can be handled. Capture is optional and disabled until you enable it. Content scripts inspect clicked links under your configured file and site rules. Read-only webRequest observers keep bounded, in-memory URL/method/initiator/tab metadata for up to 30 seconds to distinguish public GET downloads from POST requests. Redirect destinations for Flux's own requests are held for up to five seconds so each hop can be validated. Credentials, cookies, authorization headers and POST bodies are not read or forwarded. Temporary browser-fallback decisions expire after one minute. Linked original browser rows retain Chrome's download ID, start time, public source reference, filename, progress and status locally. For trusted blob/data download clicks, up to 64 single-use page attribution hints retain a public source-page URL, parent hostname, kind and random filename prefix in session storage; they expire logically after 15 minutes and are pruned on access. No data URL payload or generated file body is sent to Flux messaging or stored in its history. Legacy review candidates from an earlier version can remain in session storage until dismissed or the session ends. User-invoked link/media discovery reads up to 2,000 link URLs and direct media URLs from an accessible web page for review. Batch imports and exports process the URL lists you choose locally; exported lists can include signed URL queries. Blob/data entries are excluded from exported link lists. These features do not upload observations to Flux servers. Notifications are optional and show a filename when a transfer is ready to save.

OPFS content remains inside Chrome until a verified file is saved to a destination you select. The optional automatic-save feature stores a directory handle locally and writes verified files into that approved folder; it can create category subfolders if enabled. Chrome can require renewed folder permission. No folder access is granted silently. Saving creates a second copy. Remove a download to delete its staged content and local record. Clear history removes completed/canceled records and their staged copies. Clean temporary data removes orphaned staging files and exported records older than the configured retention period; unfinished tracked downloads are retained. Retention cleanup is user invoked in this version. Deleting profile storage or uninstalling Flux can remove local records and staged files. Exported destination files are managed by you and are not deleted by Flux's history cleanup.

You can revoke website access and notifications in Chrome or Flux settings, disable automatic capture, exclude websites, and delete local download data. When capture is enabled, eligible clicked file links queue directly in Flux. For other native downloads, Flux can pause a known public GET, probe it without credentials, persist the replacement job, and only then cancel Chrome's transfer. Requests that cannot be reproduced safely retain their original Chrome download, which can be controlled through its linked Flux row. Removing an unfinished browser row cancels that request; removing any browser row deletes only Flux's record and leaves Chrome history and saved files intact. Chrome retains its own authentication, destination and security behavior. Original browser transfers are not staged in OPFS or hashed by Flux and may continue while the manager is closed and Chrome remains open.

Before any public store distribution, the distributor must provide publisher identity and contact information alongside this policy and reconcile it with the exact shipped version. This repository does not publish the policy or transmit any information on your behalf.
