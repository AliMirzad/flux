# Flux technical feasibility

Research baseline: **2026-10-19**, implementation notes updated for 0.10.0 on 2026-10-21. Target: desktop Chrome, Manifest V3, minimum Chrome 120. This document records platform evidence and implementation decisions. Documentation of an API is not proof that this build passed an acceptance test. Consult the test and benchmark reports for measured results.

## Execution and lifecycle

Chrome may terminate an extension service worker after inactivity, long event processing, or a slow fetch response. Worker globals are not durable. Flux therefore puts transfer execution in a dedicated module worker owned by the visible manager tab; the MV3 service worker handles browser integration. This is an architecture decision, not a guarantee against tab discard, crashes, sleep, or browser shutdown. Recovery must work without unload events. No keepalive loop is used. [Chrome service worker lifecycle](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)

Offscreen documents require the `offscreen` permission and a supported reason; `WORKERS` is a documented reason. The absence of a reason-specific time limit does not promise uninterrupted execution. Flux does not create offscreen documents. A manager tab makes the transfer's execution context and its lifetime visible to the user. [Offscreen API](https://developer.chrome.com/docs/extensions/reference/api/offscreen)

## Permission strategy

Declare optional HTTP(S) host patterns so a user gesture can request the needed host at runtime. Chrome host match patterns are scheme/host scoped; path restrictions do not isolate a particular file, and ports are not a fine-grained permission boundary. Explain this in the grant UI. A URL is validated before any host request. Existing grants can be removed by the user. [Permissions API](https://developer.chrome.com/docs/extensions/reference/api/permissions)

The shipped manifest requests `contextMenus` for link actions, `alarms` for schedule wake messages, `storage` for integration state, `downloads` for opt-in native takeover/review and explicit browser fallback, read-only `webRequest` for short-lived method/initiator and own-response redirect metadata, and `activeTab`/`scripting` for user-invoked media inspection and opt-in page capture. Notifications are optional. HTTP(S) host access is optional: manual input requests a destination origin, while the explicit automatic-capture action requests website-wide HTTP/HTTPS access once. The build does not request `unlimitedStorage`; quota/eviction constraints apply and users can request persistent storage. No cookies, debugger, nativeMessaging, webRequestBlocking, or offscreen permission is included.

Read-only metadata observation uses the MV3-supported webRequest events without webRequestBlocking or header mutation. It does not expose cookie or authorization fields to Flux. [webRequest API](https://developer.chrome.com/docs/extensions/reference/api/webRequest)

## Experimental acceptance gates

Record browser version, OS, file size, source URL/server behavior, bytes received, output digest, and execution-context behavior for every acceptance run. Required experiments include: service-worker suspension during transfer; manager closure and reopen; two manager tabs; browser-context restart; full browser restart; permission revocation; quota failure; canceled/failed export; changed identity; ignored/incorrect ranges; validated CDN redirects and blocked private/downgrade/loop targets; encoded content; and corrupt/truncated stored ranges. Keep DevTools closed for lifecycle tests because debugging can alter worker lifetime. These gates remain unverified until an actual run is recorded.

## Store constraints

Ship all executable JavaScript/WASM in the package, document each permission and data flow, and align the privacy policy with actual behavior. No telemetry or backend is required. Store approval is a separate external review, never implied by a successful local build. [MV3 program policy](https://developer.chrome.com/docs/webstore/program-policies/mv3-requirements), [Use of permissions](https://developer.chrome.com/docs/webstore/program-policies/permissions)
